Where to send what.

Bugs and features land as public GitHub issues so we can track, label, and ship fixes. Discord is for chat; the feedback board is for lighter ideas.

  • Bug on GitHub Opens the bug report form — needs a free GitHub account
  • Feature on GitHub Opens the feature request form for enhancements

  • Discord Releases, chat, and early-access notes — not a substitute for bug reports
  • Reporting guide Crash reports, traces, and what to include
  • Open issues Check duplicates before you file

Reporting bugs

A useful report is reproducible.

  • 1. Search first

    Skim open issues and the feedback board so we do not get the same crash three times.

  • 2. Say what you did

    Steps, expected vs actual, viewer version, OS, and GPU. One clear path beats a vague “it broke.”

  • 3. Attach evidence

    Dev Toolbox copy tools, crash “Copy trace,” or a short log snippet. Prefer that over dumping entire log files.

  • 4. File on GitHub

    Use the bug form below or in the viewer Help / “Report a bug.” That creates a tracked issue on ape-squared/Block-Viewer.

Crashes can also publish from the crash window after you connect GitHub in-app — see Reporting bugs. This hub is for Block Viewer only, not Block-GPPI.
